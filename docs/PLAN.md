# Plan

Titanic 4D is an interactive, source-backed 3D reconstruction of the sinking of RMS Titanic
(night of 14–15 April 1912), navigable in space and time, published at
<https://www.titanic-4d.org>. This document lists the milestones, their acceptance criteria and
the known risks. Progress is tracked in [STATUS.md](STATUS.md); architectural decisions are
recorded in [DECISIONS.md](DECISIONS.md).

## Success criteria

| #   | Criterion     | Verified by                                                                                                                                                                                                |
| --- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Fidelity      | Every displayed state derives from a `data/` record carrying `source_ids`, `certainty` and `note`; schema validation in CI; "Sources" panel for the current instant                                        |
| 2   | Time          | Scene state is a pure function of time `t`; unit tests for determinism and for forward, backward and jump equivalence                                                                                      |
| 3   | Photorealism  | FFT night ocean, astronomically computed sky, data-driven lighting, PBR, AgX tone mapping; visual review against documented references at each milestone                                                   |
| 4   | Performance   | 60 fps target, 30 fps minimum at 1080p on a recent integrated GPU at "medium" quality; first interactive render under 5 s at 50 Mb/s; initial JavaScript at most 400 kB compressed; budgets enforced in CI |
| 5   | Accessibility | WCAG 2.2 level AA; full keyboard operation; screen readers; `prefers-reduced-motion`; complete text alternative; axe-core in CI and documented manual tests                                                |
| 6   | Deployment    | Canonical origin answers 200 with a valid Let's Encrypt certificate and security headers; three secondary hosts redirect with 301; redeploy on push to master                                              |

## Milestones

Each milestone ends with typecheck, lint, unit tests, build, budgets and the end-to-end suite
passing, the documentation updated, and the results recorded in STATUS.md.

### M0 — Skeleton

Tooling (TypeScript, Vite, Biome, Vitest, Playwright, axe-core), CI workflow (typecheck, lint,
tests, build, budgets, end-to-end, container), Dockerfile and Caddyfile, accessible empty page.

Done when: `pnpm check` passes; the end-to-end suite passes on the WebGL 2 and WebGPU projects;
the container image passes `tools/verify-server.ts`.

### M1 — Data and TimelineModel

Zod schemas and exported JSON Schema; sources registry; chronology, ship geometry, compartments,
flooding, trim and heel curves, lifeboats, rockets, wireless, lighting, break-up, wreck,
environment, casualty counts; time conversion (ship's time, New York time, GMT); pure
`TimelineModel` evaluating the state at any `t`.

Done when: all data files validate; every record has sources and a certainty; tests prove
determinism and that forward, backward and jump evaluation give identical states.

### M2 — LOD0 scene and complete timeline

Procedural LOD0 ship from the dimensions in `data/`; WebGPU renderer with WebGL 2 fallback;
camera modes; timeline control with playback (×1 to ×600), reverse, pause and event bookmarks;
URL state; sourced information panel; text narrative view.

Done when: the application is usable end to end with keyboard, pointer and touch; screenshots at
the six key instants exist for both backends.

### M3 — Ocean, exact sky, lighting

FFT ocean (near-flat sea) with Gerstner fallback; star field and planets computed for date, time
and position; Moon below the horizon; cold haze; ship lighting and its data-driven extinction;
AgX tone mapping.

Done when: sky tests match reference ephemerides; lighting follows the dataset; visual review
recorded.

### M4 — Flooding, trim, heel, boats, rockets, break-up, descent, wreck

Water levels per compartment, hull attitude from the curves, lifeboat launches with displayed
uncertainty, distress rockets within WCAG flash limits, bottom-up break-up at 15–17° of trim,
descent of both sections, wreck site on the seabed.

Done when: every animated element is driven by `TimelineModel`; no state depends on frame history.

### M5 — LOD1/LOD2, post-processing, quality settings

Headless Blender pipeline (Python, `bpy`, run through uv; ruff and ty clean) producing
Meshopt-compressed GLB and KTX2 textures reproducibly in CI; post-processing; quality presets;
gamepad input.

Done when: assets are regenerated by one command and by CI; "medium" preset meets the
performance budget.

### M6 — Accessibility, UX polish, support, legal notice, performance

Manual accessibility audit documented in `docs/ACCESSIBILITY.md`; ARIA live announcements;
reduced motion; "Support Titanic 4D" entry and About page; Legal Notice page; security.txt;
sitemap; performance pass.

Done when: axe-core reports no violation on every view; legal and support content match their
single source of truth under test.

### M7 — Deployment

Dokploy application built from the Dockerfile, four domains with Let's Encrypt certificates,
automatic deployment on push to `master`, post-deployment verification.

Done when: the checks in `docs/DEPLOY.md` pass against the live hosts and are recorded in
STATUS.md.

## Risks

| Risk                                                         | Mitigation                                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Historical data is incomplete or disputed                    | `certainty` field on every record; competing positions recorded, never silently resolved                     |
| three.js WebGPU build weighs on the JavaScript budget        | Renderer loaded as a separate chunk; budget measured on every build; tree-shaken imports from `three/webgpu` |
| WebGPU unavailable (Linux, Firefox for Android)              | Automatic WebGL 2 backend; both backends exercised by the end-to-end suite                                   |
| Visual baselines differ between machines                     | End-to-end tests always run in the pinned official Playwright image with software rasterisation              |
| Procedural and agent-built models fall short of photorealism | Exact silhouette, proportions and layout first; detail added by LOD; gaps listed in STATUS.md                |
| Distress rockets could exceed flash thresholds               | Luminance ramping and frequency limits tested against WCAG 2.3.1                                             |
| Subject is a human tragedy                                   | Sober tone; no depiction of victims; no distress sound design; support invitation kept out of the narrative  |
| Deployment tools unavailable in a session                    | Artefacts and `docs/DEPLOY.md` kept complete so that M7 can run from any session with Dokploy access         |
